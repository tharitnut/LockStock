ทำไมโหมดปลอดภัยถึงไม่ขายเกินสต็อก? (Concurrency Architecture)

เมื่อมีคำสั่งซื้อหลายคำขอเข้ามาแย่งซื้อสินค้าชิ้นเดียวกันพร้อมกันในหน่วยมิลลิวินาที:

  1. ACID Transaction: ทุกการสั่งซื้อเริ่มต้นด้วยคำสั่ง BEGIN TRANSACTION
  2. Row-level Lock: ดึงข้อมูลสินค้าด้วย SELECT ... FOR UPDATE โดยเรียงลำดับ ID จากน้อยไปมากเสมอ (Ascending Order) เพื่อขจัดปัญหา Deadlock
  3. Exclusive Lock: คำขอแรกที่เข้าถึงจะได้ Lock แถวสินค้านั้นไว้ คำขออื่นที่เข้ามาพร้อมกันจะหยุดรอ (Block) จนกว่าคำขอแรกจะเสร็จสิ้น
  4. ตรวจเช็คและตัดสต็อก: เมื่อคำขอลำดับถัดไปได้รับ Lock จะได้ข้อมูลสต็อกล่าสุดที่อัปเดตแล้วจริง จึงตรวจสอบพบว่าสต็อกหมด และตอบกลับด้วย 409 INSUFFICIENT_STOCK ทันที โดยสต็อกไม่ติดลบ
  5. Audit Ledger: ทุกการตัดสต็อกจะบันทึกลงสมุดบัญชี stock_movements เสมอ ทำให้ตรวจสอบย้อนหลังได้ตลอดเวลา
